#### Description

`Salesforce/blip-vqa-base` is the Transformers-format release of the BLIP *base* model fine-tuned for visual question answering, from "BLIP: Bootstrapping Language-Image Pre-training for Unified Vision-Language Understanding and Generation" (Li, Li, Xiong, Hoi, arXiv:2201.12086), converted by the Hugging Face team and pinned here to revision `787b3d35d57e49572baabd22884b3d5a05acf072` (the Hub's `main` on 2026-09-14). The snapshot `config.json` declares `BlipForQuestionAnswering`: a 12-layer ViT-B/16 image encoder at 384×384 (hidden size 768, 12 heads, 576 patches plus a class token), a 12-layer BERT-style text encoder (hidden size 768, vocabulary 30,524, maximum 512 positions) whose layers cross-attend to the image features, and a 12-layer text decoder of the same shape that generates the answer — 361,230,140 parameters in the 1.54 GB float32 `model.safetensors`. The model was pretrained on 129M image–text pairs (COCO, Visual Genome, Conceptual Captions 3M/12M, SBU and a LAION subset, bootstrapped with BLIP's captioning-and-filtering procedure) and fine-tuned on VQA v2 (with Visual Genome QA, per the paper) as an answer-generation task. At inference the processor (`BlipImageProcessor`, `preprocessor_config.json`: resize to 384×384 without preserving aspect ratio, CLIP mean/std) encodes the image, the BERT tokenizer encodes the question, the question encoder fuses the two, and the decoder generates the answer text. No adaptation happens at inference. What this repository adds is packaging and a bounded adaptation contract: `verify_snapshot` and `stage_missing_files` (manifest digest checking and fresh-clone staging), `BlipVQAPipeline.from_pretrained` (verified local loading with `trust_remote_code=False`), `answer` (input validation, whitespace-collapsed question, greedy decoding under a caller-owned `max_new_tokens`, a `truncated` flag), `normalize_answer`, `exact_match`, `anls`, `vqa_accuracy`, the `validate_inputs` and `evaluation_report` stage helpers, corpus-level metrics with two non-neural baselines (`metrics.py`: constant answer and question-prefix majority), a digest-pinned real VQA corpus read annotation-column-only with per-photograph pins (`samples.py`: VizWiz-VQA, validated and split by image without leakage), supervised fine-tuning of the answer decoder's last *k* blocks plus its head transform and bias (`adapt`, default 2 of 12) with validation-VQA-accuracy epoch selection over vision features computed once per training image, and a safetensors adapter (`save_artifact` / `from_artifact`) that carries only the trained tensors and is bound to the base weight digest.

#### Intended Use and Limitations

The uses below are the ones the package was built to support; everything else is either out of scope (§Out-of-scope use cases) or prohibited (§Use cases).

###### Primary Intended Uses

The task is open-ended visual question answering with short generated answers: input one image (`PIL.Image.Image`, any mode, converted to RGB), one natural-language question (up to 256 characters) and a token budget; output one short answer string, the number of tokens generated and whether the budget was exhausted. Envisioned applications are interactive image lookup ("what color is the car?", "is there a dog?", "how many people?"), attribute and presence checks over photo collections, accessibility aids that let a user ask about a picture, and prototyping of multimodal assistants — with the answer checked against the image by a human or a downstream rule. The second intended use is bounded domain adaptation: given 8–5,000 `{id, image, question, answers}` records with accepted answers on the operator's own photographs, `adapt` fine-tunes the answer decoder's last two blocks and its head transform and bias (19,526,204 parameters, about 5 % of the model) for a few epochs on each record's majority answer, selects the epoch by validation VQA accuracy, and `save_artifact` exports the trained tensors as a ~78 MB safetensors adapter that `from_artifact` applies on top of the digest-verified base — the recorded run lifts held-out VizWiz VQA accuracy from 0.239 to 0.728 in about six minutes of CPU training, mostly by learning the `unanswerable` convention the base model lacks and partly on the answerable questions. Within DIMER the pipeline is an inference component and a zero-configuration baseline for VQA plus a recipe for adapting it to one image population and answer convention, not a certified answerer for any specific image domain.

###### Primary Intended Users

Intended users are machine-learning engineers, computer-vision developers, and data analysts integrating visual question answering into research prototypes or internal tooling, and adapting it to an image population for which they hold a small set of questions with accepted answers. A user is expected to understand that the output is *generated text* — it carries no probability, no correctness signal and no location in the image, and the model answers every question, including unanswerable ones, with equal fluency — that answers follow VQA v2's style (one to three words: a colour, a count, a noun, `yes`/`no`) rather than sentences or reasoning, that the token budget is theirs to set, that the model was fine-tuned on everyday photographs with English questions so drawings, documents, diagrams, non-English questions and expert domains are distribution shifts, that greedy decoding is reproducible on a fixed device but GPU and CPU outputs need not match, that VQA accuracy, exact match, majority match and ANLS measure agreement with accepted answers rather than usefulness and are only comparable across runs scored on the same answers, and that a fine-tuned adapter is only as good as the split discipline behind it — every question on an image must stay in one split, and images from few photographers or sessions must be split by source, or the validation score is inflated. Users who need text reading, answer grounding, captioning or batch throughput are expected to know none of that is provided here.

###### Out-of-scope use cases

1. **Capability boundary:** no answer localisation or evidence region, no confidence, no abstention in the base model (it cannot say "I cannot tell"; an adapter trained on a corpus with an `unanswerable` convention learns to emit that word, which is a learned answer, not a calibrated refusal), no text reading (BLIP-VQA is not an OCR model), no captioning (a separate checkpoint), no batching at inference (each question is a full encoder pass), no sampling or beam search, and no counting, spatial or commonsense reasoning beyond what VQA v2's answer distribution rewards — the smoke run counted `2` trees where one was drawn. Not a general training framework: `adapt` fine-tunes only whole blocks of the answer decoder (1–12 of them, the last *k*) plus the head's transform and bias, with AdamW, a fixed learning rate, no scheduler, no mixed precision, no gradient accumulation and no early stopping beyond epoch selection; the vision encoder, the question encoder, every embedding and the head's projection weight (tied to the word embeddings) are never modified, so it cannot teach the model a new script or a new visual domain, only a new answer distribution over what the frozen encoders already see.
2. **Input boundary:** `answer` rejects non-PIL images (`TypeError`), sides below `MIN_IMAGE_SIDE = 16` px or above `MAX_IMAGE_SIDE = 4096` px, empty or non-string questions, questions longer than `MAX_QUESTION_CHARS = 256`, and budgets outside `[1, MAX_NEW_TOKENS = 32]` (`ValueError`/`TypeError`). Every image is resized to 384×384 without preserving aspect ratio, so thin panoramas are squashed and detail below roughly 1/24 of the shorter side is lost; fine text, small objects and subtle colours are outside the model's resolution. Datasets for `validate_dataset`, `evaluate` and `adapt` are lists of `{id, image, question, answers}` records: fewer than `MIN_RECORDS = 8` or more than `MAX_RECORDS = 5000` records, a duplicate or malformed `id` (pattern `^[A-Za-z0-9_.:-]{1,64}$`), an image file that is missing, undecodable or outside the side ceilings, a question the inference checks would refuse, an empty `answers` list or an empty answer string is rejected with `ValueError`; `evaluate` accepts 1–`MAX_EVAL_RECORDS = 2000` records; `adapt` requires at least `MIN_RECORDS` training records and refuses `epochs` outside 1..20, `batch_size` outside 1..64, `lr` outside (0, 1e-3] or `trainable_decoder_layers` outside 1..12. `load_artifact` refuses an adapter whose `format`, `format_version`, `base_model` id, revision or `weight_sha256` differ from the constants, whose tensor set differs from what its recorded `trainable_decoder_layers` implies, whose tensor names are not `text_decoder.*`, or whose file digest differs from its manifest.
3. **Input boundary:** the fine-tuning data is VQA v2 — COCO photographs of everyday scenes with crowd-sourced English questions and ten short human answers each. Drawings, screenshots, documents, charts, medical or satellite imagery, non-English questions and questions whose answer is a sentence fall outside what the upstream authors evaluated and what this repository measured; results on them are undefined, not merely degraded. An image with no content still produces an answer (see §Risks and harms). The adaptation sample is VizWiz — photographs by blind users, spoken questions, an `unanswerable` convention — and the recorded gain is specific to that population and convention.
4. **Decision boundary:** not for autonomous decisions that act on answers — content moderation, safety or compliance checks, medical or accessibility-critical descriptions, surveillance or identification — without a human comparing the answer with the image, and a locally measured VQA accuracy on the deployment's own labelled question/answer sets. A gain on the operator's validation split is not a release decision: it is a single seeded split of one corpus with no dispersion estimate, and an adapter that learned to say `unanswerable` can say it wrongly.

#### Factors

###### Groups

This pipeline is human-centric wherever the image contains people and the question asks about them: VQA v2 questions include "what is the man doing?", "how old is the woman?", "what race is the person?", and the model answers them from COCO-style photographs whose demographic composition (skewed towards Western, adult, lighter-skinned subjects per published audits of COCO) and whose annotators' conventions shape the answer distribution. Neither the upstream authors nor this repository audited answer accuracy or answer *content* by the depicted person's gender, age, skin tone, disability, dress or setting, nor the pretraining web corpora for stereotyped image–text pairs; the model will answer a question about a person's gender, age, occupation or emotion with a confident guess and no signal that it is a guess. The adaptation sample adds one population the base model never saw: VizWiz photographs are taken by blind and low-vision people, often blurred, poorly framed or dark, with questions spoken about their own surroundings — and the recorded per-category breakdown (`other`, `yes/no`, `number`, `unanswerable`) is the only group-level evidence in this repository. Non-human groups whose accuracy is unknown, not known to be equal: non-photographic images (the tutorial's cartoon is one; the model miscoloured its door), non-Western scenes, objects and clothing, low-light and low-resolution captures, and questions phrased in non-native or non-English forms. An operator whose images contain people is responsible for a fairness audit on their own image set, stratified by depicted group and question type, before relying on the output or adapting to it — and for deciding which questions about people are permitted at all (see §Use cases).

###### Instrumentation

The upstream pretraining "instrument" is web image–text pairs at whatever resolution and quality the source sites served, filtered by BLIP's own captioner/filter, and the fine-tuning instrument is COCO photography (consumer cameras, Flickr uploads) with crowd-sourced questions. Inference images arrive from whatever produced them — a phone camera, a screenshot, a render, a scanner — and resolution, exposure, colour balance, compression and aspect ratio all change the visual evidence; the fixed 384×384 resize discards aspect ratio and detail regardless of the source, so a 4096×4096 input carries no more information than a 384×384 one. The pipeline validates type, size and question length only; it cannot detect an unusual capture, a non-photographic image, or a question that the image cannot answer. The adaptation sample's instrument is a blind user's phone camera and voice: framing, focus and exposure are uncontrolled by design, the question is a transcribed utterance ("Ok. There is another picture I hope it is a better one."), and ten crowd workers supplied the answers, disagreeing often enough that `unanswerable` sits among the ten answers of most questions in the sample — which is why majority match is reported beside the benchmark's partial-credit accuracy. The synthetic tutorial scene (flat Pillow shapes, no texture, no lighting) is itself a rendering instrument unlike any photograph, which is why the smoke run's two misses are recorded rather than treated as anomalies.

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `safetensors==0.8.0`, `numpy==2.5.3`, `pillow==11.3.0`, `huggingface-hub==0.36.2`, `pyarrow==25.0.1`, float32 on CPU; CUDA is used automatically when visible (float32). Inference, measured on the reference machine with the GPU hidden (`CUDA_VISIBLE_DEVICES=-1`) and the Hub offline (`HF_HUB_OFFLINE=1`): `verify_snapshot` on the 8-file, 1.54 GB snapshot 0.82 s; load 5.6–5.8 s; one 640×480 drawn scene, ten questions at the default budget, 0.19–0.54 s per question (first call slower; every answer 2 tokens including end-of-sequence); a 4096×4096 blank image 0.66 s — cost is one 576-patch encoder pass plus a few decoder steps per question, roughly independent of the input resolution after the resize. Adaptation on the same machine, from the committed notebook's recorded run (Intel Core Ultra 9 275HX, CPU float32): reading the cached VizWiz annotations, re-hashing the 240 cached photographs and cutting 140 / 40 / 60 records by image took 2.6 s; scoring the frozen model on the 60 test photographs took 56.5 s (VQA accuracy 0.239, exact match 0.333, majority match 0.167, ANLS 0.353; constant-answer baseline VQA accuracy 0.683 / exact match 0.783 / majority match 0.583 / ANLS 0.783; question-prefix baseline 0.622 / 0.717 / 0.567 / 0.717); four epochs of AdamW over 140 training photographs at batch 8 with the answer decoder's last two blocks and head trainable (19,526,204 of 361,230,140 parameters, `lr=5e-5`, weight decay 0.01, gradient clipping 1.0, seed 0), the vision features computed once, took 341.8 s including the per-epoch validation scoring (validation VQA accuracy 0.167 frozen → 0.683 → 0.783 → 0.758 → 0.775; epoch 2 selected); re-scoring the test split gave VQA accuracy 0.728, exact match 0.817, majority match 0.667 and ANLS 0.817; the adapter is 78,112,280 bytes over 57 tensors, and the reloaded pipeline reproduced 8/8 answers. Counter-examples recorded during the build on the same split on the RTX 5070 Ti (CUDA, float32; 30-question validation split of an earlier draw): two blocks at `lr=5e-5` for four epochs reached test VQA accuracy 0.728 (`other` 0.57, `unanswerable` 0.91); four blocks at `lr=5e-5` for six epochs 0.722; two blocks at `lr=1e-4` for six epochs 0.756 (best epoch 1); six blocks at `lr=3e-5` for six epochs 0.761 — all within the noise of a 60-question test split, so the default stays the smallest configuration. The CUDA path was executed by the model-backed test suite on that GPU (answer, a one-epoch adaptation and the artifact round trip) and by those probes; the Hub-download path was executed by the earlier Kaggle run of the inference-only notebook. Data environment: the model assumes the image is an everyday photograph and the question a VQA v2-style English question with a short answer; the synthetic tutorial scene violates the first assumption on purpose (flat cartoon), which is where the recorded misses come from, and VizWiz violates the population and the answer convention, which is where the recorded gain comes from. Documents, diagrams, non-English questions and other populations violate it to degrees this repository did not measure, and the pipeline reports no signal when they do.

#### Metrics

###### Performance Measures

Four performance measures, named exactly as the code names them: `vqa_accuracy` — the VQA v2 / VizWiz benchmark measure `min(number of accepted answers the normalised prediction equals / 3, 1)`, which needs several human answers per question (VizWiz supplies ten) and degenerates to a graded exact match on authored data; `exact_match` against any accepted answer; `majority_match` against the question's most frequent accepted answer (the stricter view on VizWiz, where `unanswerable` appears among the ten answers of most questions and a constant answer would otherwise score high); and `anls` — normalised Levenshtein similarity `1 − lev / max(len)`, maximised over the accepted answers, scored 0 below `ANLS_THRESHOLD = 0.5` — all after lower-casing, punctuation removal and whitespace collapsing, implemented in `src/blip_vqa_pipeline/pipeline.py` and averaged over a dataset by `vqa_metrics(predictions, golds)` in `metrics.py` (each in 0..1, plus `empty_rate`). `vqa_accuracy` gives partial credit to a minority answer, `exact_match` is generous on corpora with disagreeing annotators, `majority_match` is unforgiving of any minority answer, and `anls` rewards near-misses; reading only one hides what the others show, and all four should be read per category (`by_category` in the notebook) because the corpus mix is uneven. `pipe.evaluate(records)` answers a validated dataset and returns them with the verdict `measured` (≥ `MIN_SCORED_RECORDS = 50` records) or `measured-small-sample`, the elapsed time and the model identity; `constant_answer_baseline(records)` scores one fixed answer everywhere (`unanswerable` by default) and `question_prefix_baseline(train, records)` the training majority answer for the question's first two words — a lookup with no model and no image. VQA accuracy selects the epoch in `adapt`. The public per-image `evaluation_report(results, golds=None)` helper is unchanged: the `exact_match` rate and the mean `anls` over the questions of one image plus one per-question entry with verdict `sample-sanity`, or `not-measurable` naming the labelled set that would be required when no accepted answers are supplied. Every result also carries descriptive fields that are not performance measures: `new_tokens` and `truncated`. The upstream paper's VQA v2 test-dev accuracy for its ViT-B models (about 78, upstream-reported) is not reproduced or claimed by this pipeline. Recorded values on the seeded VizWiz test split (60 photographs, ten answers each, CPU float32, `max_new_tokens` 10): constant answer `unanswerable` VQA accuracy 0.683 / exact match 0.783 / majority match 0.583 / ANLS 0.783; question-prefix majority 0.622 / 0.717 / 0.567 / 0.717; frozen VQA accuracy 0.239 / exact match 0.333 / majority match 0.167 / ANLS 0.353 (per category: `other` 0.23, `unanswerable` 0.08, `yes/no` 1.0 on 5 questions); adapted (answer decoder's last two blocks + head, best of four epochs) 0.728 / 0.817 / 0.667 / 0.817 (per category: `other` 0.57 against 0.48 for the constant answer, `unanswerable` 0.91 against 1.00, `yes/no` 1.0 on 5 questions); the drawn scene's seven authored questions after adaptation the same five of seven exact answers as the frozen model (`exact_match` 0.714, verdict `sample-sanity`; the two recorded misses unchanged). The frozen model loses to the constant answer on the whole set because it never says `unanswerable`; the gain is read per category and on majority match, not as a rescue.

###### Decision thresholds

No score threshold exists in the model: it generates tokens until end-of-sequence or the budget and nothing is filtered or abstained. The decision parameter is the **token budget** `max_new_tokens`, default `DEFAULT_MAX_NEW_TOKENS = 10` (a phrase-sized budget chosen by this repository; every smoke answer needed 2 tokens including end-of-sequence, and the upstream README example uses the library default) with ceiling `MAX_NEW_TOKENS = 32`. A budget that is too small is reported, not hidden: `truncated` is true whenever `new_tokens` reaches it (a budget of 1 flags the one-token answer `dog` as truncated even though it was complete — the flag is conservative), and the caller should raise the budget and rerun. The evaluation helpers carry two published conventions, `ANLS_THRESHOLD = 0.5` and `VQA_ACCURACY_DIVISOR = 3`, neither tuned here. Decoding is greedy (`do_sample=False`) with no temperature, beams or repetition penalty. The one selection rule in the adaptation path is explicit: `adapt` keeps the epoch with the highest validation VQA accuracy (epoch 0 is the frozen model, so a run that never improves returns the base weights unchanged) and reports `best_epoch` and the per-epoch history; the training target is the majority answer of each record's accepted answers (ties to the first). Whether the resulting gain on the test split is worth deploying — and whether a learned `unanswerable` is an acceptable refusal for the deployment — is the operator's decision and no threshold is shipped for it.

###### Approaches to uncertainty and variability

Every reported corpus metric is one value on one seeded split of one corpus: the 240-question sample was drawn once from the pinned shard at build time (seed 42), `build_sample_dataset(seed=42)` fixes the image assignment into 140 / 40 / 60, `adapt(seed=0)` fixes the shuffle order, and no repetition over seeds or splits is performed, so no confidence interval or standard deviation is available and none is claimed — the gain on the test split is a point estimate whose spread is unknown, the per-category values rest on as few as 5 questions, the validation split that picks the epoch holds 40, and the drawn scene re-answered after adaptation is seven authored pairs on one image with the verdict `sample-sanity`. The build's own probes show the spread: the same split gave test VQA accuracy 0.722–0.761 across five configurations on the GPU. When accepted answers are supplied to the per-image `evaluation_report`, it says so (`estimation: "<n> question(s) on one image, no dispersion estimate"`). Inference is deterministic for a given image, question, budget, weights, device and library versions: there is no sampling and no seed to set, but because decoding is autoregressive a single differing token changes the rest of the answer, and CPU and CUDA outputs need not match; the drawn scene uses no text rendering, so its bytes do not depend on the Pillow build. Training is deterministic on one CPU for one seed and library set but is not bit-reproducible across devices or `torch` builds. Ten VizWiz answers disagree often, so the majority answer that trains the model is itself a vote. A caller who needs an accuracy estimate must supply labelled question/answer sets (several human answers per question for VQA accuracy) and compute over many images or bootstrap resamples themselves; a caller who needs a confidence per answer has none from this model.

#### Ethical considerations and biases

No external ethics board, red-team, or population-specific clearance reviewed this repository or, to our knowledge, the upstream checkpoint; nothing below should be read as implying one.

###### Data

The upstream paper describes pretraining on 129M image–text pairs from COCO, Visual Genome, Conceptual Captions 3M and 12M, SBU Captions and a 115M-image LAION subset — web-scraped pairs whose images and captions can include real, identifiable people, copyrighted photographs and stereotyped or offensive text, filtered only by BLIP's own learned filter — and fine-tuning on VQA v2 and Visual Genome QA, whose images are COCO/Flickr photographs of people and everyday scenes with crowd-sourced questions and answers; personal data in the training corpora is therefore present by construction. Neither was audited here. This repository distributes code, tests, and documentation; it does not distribute the 1,538,800,584-byte `model.safetensors`, which is staged locally under `weights/blip-vqa-base/` and git-ignored. The adaptation sample is not shipped either: `fetch_annotations` reads, at run time, the four text columns of one object in the Hub dataset repository `lmms-lab-encoder/VizWiz-VQA` at revision `d428a2dae984f79cf1b9d99467dfa883e0c30686` (`data/val-00000-of-00005-7775fd61bc6a3d98.parquet`, 405,819,917 bytes, SHA-256 `62a5fddb…`; the declared size and digest checked against the pins before any byte is read, only the parquet footer and those columns fetched over HTTPS range requests, the decoded columns refused unless their SHA-256 matches `00b476dd…`), and `fetch_images` fetches the 240 photographs of the sample one by one from `vizwiz.cs.colorado.edu`, each pinned by size and SHA-256 in `samples.py` and refused on any mismatch; both are cached under `weights/vizwiz/` (git-ignored). VizWiz-VQA (Gurari et al., 2018; CC BY 4.0) consists of photographs taken by blind people of their own surroundings — homes, food, medicine, screens, documents, sometimes people — with their spoken questions and ten crowd-sourced answers; the images can show personal effects, addresses, prescriptions and faces, and the operator should treat them as personal data even though the dataset is public. The 240-question sample and its splits are reproducible from the digests and the seeds; the sample's `unanswerable` share (about half) is the shard's own mix, above the benchmark's quarter. The weights are BSD-3-Clause and redistributed unmodified; an adapter trained on the sample is a derived work of both and inherits the corpus's attribution obligation. Nothing in this corpus is a substitute for the operator's own photographs: BYOD records pass through the same validation and are written to `outputs/…_train.jsonl` in the notebook, so a photograph set with its questions and answers is restricted data the moment it is loaded. The operator must audit the images they submit or train on for personal, proprietary, or otherwise restricted content; the pipeline performs no such check and will answer "what is the woman's age?" as readily as "what color is the house?".

###### Human Life

This pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, or housing, and it has not been validated or certified for any of them by this repository, the upstream authors, or any regulator. Its only validation is the offline unit suite (35 tests, plus 6 model-backed tests that run when the snapshot is staged) and the CPU and GPU runs recorded in this repository on one drawn scene and one VizWiz sample. Foreseeable but unintended sensitive uses — describing images to blind or low-vision users where a wrong answer misleads (the VizWiz population is exactly that, and a learned `unanswerable` is a guess like any other), screening user-uploaded images for prohibited content, answering questions about people's identity, ethnicity, health or emotional state, reading medical or safety imagery, or fine-tuning on such material — would be admissible only with human review of every answer against the image (the model invents an answer when none exists and gives no signal), a locally measured accuracy on the deployment's own labelled image/question sets stratified by depicted group, a documented budget policy with `truncated` handling, an explicit list of question types that are refused before they reach the model, and whatever regulatory clearance the domain requires.

###### Mitigations

- **Supply-chain integrity:** `MODEL_REVISION` is a 40-hex commit; `stage_missing_files` refuses a manifest whose `modelId`/`revision` differ from the package constants and fetches only manifest-listed files at that revision when `allow_download=True`; `verify_snapshot` then checks all 8 listed files' byte sizes and SHA-256 before any load; `from_pretrained` loads only from the verified directory with `local_files_only=True`, always passes `trust_remote_code=False`, and the model libraries are imported only after the snapshot is accepted (`tests/test_import_boundary.py`). The upstream `pytorch_model.bin` (pickle) and `tf_model.h5` (TensorFlow port) are neither listed nor loaded. A test flips one hex digit of a manifest digest and asserts the loader refuses; another asserts a foreign manifest is refused.
- **Input integrity:** the public `validate_inputs(image, questions, *, max_new_tokens)` stage applies exactly the checks `answer` applies (both route through one shared private checker) and returns an input manifest recording the schema, the ceilings, the observed input, the checked questions, the budget and the verdict; `validate_image` rejects non-PIL inputs and sides outside 16–4096 px; empty, non-string or over-long questions and out-of-range or boolean budgets are rejected; `answer` raises on a malformed runner result; `evaluation_report` rejects mismatched or empty accepted-answer lists; `vqa_accuracy` rejects an empty answer set.
- **Dataset integrity:** `fetch_annotations` checks the shard's declared size and LFS SHA-256 against the pins through the Hub's file metadata before reading, fetches only the parquet footer and the four text columns, and verifies the decoded columns' SHA-256 and the row count; `fetch_images` accepts only the 240 pinned question ids, re-hashes every cached file, refuses any fetched file whose size or SHA-256 differs from its pin, spaces requests and retries transient errors a bounded number of times; `validate_dataset` enforces the record schema, the id pattern, the size bounds, opens and decodes every image, applies the inference checks to every image and question, requires at least one non-empty accepted answer, and returns a content digest; `check_split_disjoint` fails on any image id shared between splits; `build_sample_dataset` and `split_dataset` keep every question on an image in one split; no pickle and no `extractall` is used anywhere (the BYOD zip is read member by member, names flattened).
- **Training and artifact integrity:** `adapt` trains only whole answer-decoder blocks plus the head's transform and bias under an explicit `trainable_decoder_layers` bound (the tied projection weight is excluded), restores the best-epoch weights, and is transactional — if training, validation or the progress callback raises, the pre-adaptation tensors and frozen flags are restored and no adapter is attached; `save_artifact` writes a safetensors file of the trained tensors plus a manifest carrying the format tag and version, the base model id, revision and weight digest, the tensor list and the file SHA-256; `load_artifact` refuses any mismatch in those fields, a manifest with other than exactly one contained `adapter.safetensors` entry, a tensor set that differs from what the recorded configuration implies, any tensor outside `text_decoder.*`, and any digest drift — all before deserialising — so an adapter cannot be applied to a different base or altered in transit without failing. The digest detects corruption or drift of the weights relative to the adjacent manifest; it is not authenticity against an actor who can replace both files.
- **Reproducibility:** exact `==` pins in `pyproject.toml`; greedy decoding with no sampling; every result carries `model_id`, `model_revision`, the checked question, the budget, `new_tokens`, `truncated`, the device and the dtype; every evaluation carries the model identity and the dataset digests.
- **Refusals:** no batching at inference, no download without the explicit flag, no Hub access at inference time, no sampling, no pickle deserialisation, no attempt to guess whether the image can answer the question, and no filtering of question content — that refusal list is the operator's to implement in front of the pipeline.
- No statistical mitigation (class balancing, subsampling) applies: the sample's category mix is what the seeded draw produced, and the pipeline adapts to whatever records the operator validates.

###### Risks and harms

- **Invented answers:** the base model has no abstention — a blank image yielded `dog` and noise yielded `tv` in the smoke run — so an unanswerable question, a wrong image or a leading question produces a fluent, plausible answer with no signal; downstream consumers that trust the string (moderation rules, databases, LLM pipelines, screen readers) inherit the error silently. An adapter trained on VizWiz emits `unanswerable` for images it judges unreadable, which is a learned answer that can be wrong in both directions: a readable photograph declared unanswerable is a service denied, an unreadable one answered is an invention.
- **Confident guesses about people:** questions about a person's gender, age, race, health, emotion or intent are answered from appearance with the same fluency as a colour question; such answers are stereotype-driven by construction and can cause direct harm when surfaced or acted on.
- **Plausible near-misses:** `red` for a brown door and `2` for one tree are short, confident, wrong answers; only labelled evaluation on the deployment's images shows the rate, and the tutorial's 5/7 says nothing about it.
- **Automation bias:** crisp one-word answers invite trust that generated text has not earned.
- **Truncation:** an answer longer than the budget is cut (reported via `truncated`); a caller who ignores the flag ships a partial value.
- **Adaptation drift:** an adapter learns one population's answer conventions and can lose ground elsewhere; the drawn scene re-answered in the notebook is one image of evidence, not a measurement, and the artifact carries no record of what it was trained on beyond the caller's optional metadata, so a misapplied adapter is a supply-chain risk of the operator's own making — the base-digest binding stops it from loading on the wrong model, not on the wrong domain.
- **Bias amplification:** any image population or question type VQA v2 and VizWiz under-represent (non-Western scenes, non-photographic images, minority groups, non-native phrasing) is reproduced as uneven accuracy, undetected because no per-group evaluation exists beyond the per-category breakdown on one corpus.
- **Resource use:** a 1.54 GB model and ~0.2 s per question on the reference CPU with an encoder pass per question, about six minutes of CPU for the default adaptation and a ~78 MB adapter per run; a question-heavy workload scales linearly.

###### Use cases

Prohibited even where the model would work: asking questions about images of people in order to infer or record protected characteristics (race, ethnicity, religion, health, disability, sexual orientation), to identify, track, profile or surveil individuals, or to make or support decisions in employment, housing, credit, insurance, education, healthcare access, law enforcement or immigration; processing images the operator has no right to process, including intimate imagery and licence-restricted material; fine-tuning on photographs whose subjects have not consented to that processing where consent is required; deceptive uses that present generated answers as verified facts about an image or as evidence; and any use that violates the upstream BSD-3-Clause licence terms (including use of the Salesforce name for endorsement), the CC BY 4.0 terms of the tutorial corpus (attribution to its authors when an adapter trained on it is redistributed), the DIMER deployment terms, or the consent and data-protection obligations attached to the images processed. Autonomous high-consequence actions triggered by unreviewed answers are prohibited by the intended-use contract above.

## Input/output contract

- `BlipVQAPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False)` — stages missing manifest files (only with `allow_download=True`), verifies digests, loads; `device` defaults to `cuda:0` when visible, else `cpu`; float32 on both.
- `answer(image, question, *, max_new_tokens=10) -> dict` with keys `answer` (stripped decoded text), `question` (whitespace-collapsed), `image_size`, `new_tokens` (answer tokens plus the end-of-sequence token when generated), `truncated`, `generation` (`max_new_tokens`, `do_sample` false, `decoding` greedy), `device`, `dtype`, `source`, `model_id`, `model_revision`.
- `normalize_answer(text) -> str`; `exact_match(prediction, golds) -> bool`; `anls(prediction, golds, *, threshold=0.5) -> float`; `vqa_accuracy(prediction, human_answers) -> float`.
- Ceilings and constants: `MIN_IMAGE_SIDE = 16`, `MAX_IMAGE_SIDE = 4096`, `MAX_QUESTION_CHARS = 256`, `MAX_NEW_TOKENS = 32`, `DEFAULT_MAX_NEW_TOKENS = 10`, `DECODING = "greedy"`, `IMAGE_SIZE = 384`, `ANLS_THRESHOLD = 0.5`, `VQA_ACCURACY_DIVISOR = 3`, `INPUT_SCHEMA`; `DECODER_LAYERS = 12`, `DEFAULT_TRAINABLE_DECODER_LAYERS = 2`, `MAX_EVAL_RECORDS = 2000`, `MIN_SCORED_RECORDS = 50`, `MIN_RECORDS = 8`, `MAX_RECORDS = 5000`, `MIN_ANSWERS = 1`.
- `validate_inputs(image, questions, *, max_new_tokens, names) -> dict`; `evaluation_report(results, golds=None, *, sample_kind) -> dict` where `golds` holds one sequence of accepted answers per result; `verify_snapshot(path=None) -> dict`; `stage_missing_files(path=None, *, allow_download=False, downloader=None) -> list[str]`.
- `evaluate(records, *, max_new_tokens=10)` — validated records (1–2,000) → `{n, vqa_accuracy, exact_match, anls, majority_match, empty_rate, definitions, max_new_tokens, verdict, adapted, seconds, model_id, model_revision}`.

- `save_artifact(directory, metadata=None)` → directory with `adapter.safetensors` (trained tensors only) + `manifest.json` (`format` = `org.valcorza.blip-vqa-base.adapter.v1`, `format_version` `1.0`, base `id`/`revision`/`weight_file`/`weight_sha256`, `adapter` configuration, `history`, `tensors`, `files[0].sha256`); `load_artifact(directory)` verifies the manifest — the supported format and version, the pinned base, exactly one contained `adapter.safetensors` entry whose size and SHA-256 match, and the exact tensor set the recorded `trainable_decoder_layers` implies — **before** deserialising, applies the tensors in place and returns the manifest; `BlipVQAPipeline.from_artifact(directory, *, device=None, weights_dir=None, allow_download=False)` loads the verified base and applies it.
- `samples.py`: `fetch_annotations(cache_dir=None, fetcher=None)`, `fetch_images(question_ids, cache_dir=None, fetcher=None, sleep=time.sleep)`, `build_sample_dataset(annotations, seed=42, sizes=SAMPLE_SPLIT, image_paths=None)`, `fetch_sample_dataset()`, `validate_dataset(records, base_dir=None)`, `dataset_digest`, `column_digest`, `gold_texts(record)`, `check_split_disjoint(splits)`, `split_dataset(records, val_fraction=0.15, test_fraction=0.2, seed=0, base_dir=None)` (by image), `load_byod_dataset(path)` (JSON array / JSONL), `write_dataset_jsonl(records, path)`; `metrics.py`: `vqa_metrics(predictions, golds)`, `majority_answer`, `constant_answer_baseline`, `question_prefix_baseline`, `question_prefix_answers`, `question_prefix`.
